NeuroSym

An audit-oriented neuro-symbolic memory system for LLMs: constrain noisy persistent-memory writes, retrieve provenance-bearing evidence, and measure whether the resulting memory remains useful.

ThesisArchitectureEvidenceScallopEvaluationSetup gaps

Core problem statement

Research question. Given a stream of LLM-extracted, provenance-bearing candidate facts, can explicit symbolic admission control improve the correctness, consistency, and utility of persistent external memory relative to the identical memory and retrieval system without that control?

At time t, maintain memory Mt by accepting supported facts, rejecting or resolving incompatible updates under explicit schema and temporal constraints, retrieving evidence under a bounded tool/context budget, and preserving an auditable ledger of each state transition. This is more specific and testable than simply replacing long context with a knowledge graph.

Workshop framing: NeuroSym should claim auditable constrained memory transitions, not generic KG-RAG or contradiction-free long-horizon reasoning. Current rules govern a narrow set of normalized triples; they do not establish truth, correct entity resolution, global consistency, or answer correctness.

Six-cell grid

1: raw/flat. 2: unconstrained KG/flat. 3: Scallop-built KG/flat. 4: raw/RLM. 5: unconstrained KG/native-tool RLM. 6: Scallop-gated KG/native-tool RLM. The runner now makes Cells 5 and 6 share retrieval mode and tool-call budget by default, so validation is the intended experimental difference.

How Scallop is used

Scallop is a Datalog-based neuro-symbolic language supporting discrete, probabilistic, and differentiable inference. NeuroSym uses it as a discrete write validator, not as a differentiable or probabilistic learning component.

Current rule/policyEngineLimitation
Functional predicate conflictScallopReplacement is a Python confidence heuristic; multiple rival facts are not atomically reconciled.
Two-edge PART_OF cycleScallopDoes not reject cycles longer than two edges.
IS_ALIVE true/false conflictScallopOnly this predicate family is covered.
Temporal overlap, shape checks, generic/self-referencePythonTime/provenance/confidence are not declarative logic relations.

The production code creates a fresh Scallop context for a candidate and locally relevant existing facts. It can silently use a Python symbolic fallback outside fail-closed Cell 6 paths. Therefore every claimed constrained run should persist the actual engine identity, and paper results should require actual scallopy.

High-value extensions

  • Encode fact IDs, intervals, provenance, confidence, and rule version as relations and emit a declarative violation explanation.
  • Add recursive reachability for arbitrary containment cycles.
  • Use Scallop provenance to return minimal supports for accept/reject decisions and populate the existing decision ledger.
  • Model claim status and temporal validity explicitly rather than collapsing conflicts through an uncalibrated winner rule.
  • Make entity linking uncertainty explicit; string equality currently affects both validation and graph connectivity.

Only pursue differentiable Scallop if there is a defined supervised target, such as calibrating extraction confidence against gold conflict/support labels. Hard-rule satisfaction and QA must remain separately measured.

Datasets and metrics

Use HotpotQA for sentence-level evidence and answer/supporting-fact/joint EM/F1. Use 2WikiMultiHopQA for evidence-path coverage. Use LongMemEval for persistent updates, temporal reasoning, and abstention; use LoCoMo for long conversational memory. Keep LongBench-v2 as a transfer setting, not the primary validation of memory updates.

Add a controlled update stream: duplicate, functional conflict, temporal non-conflict/conflict, containment cycle, unsupported claim, alias collision, and abstention cases. Gold-label accept, reject, or replace with rule family and evidence span. Report unsafe acceptance, false rejection, replacement precision/recall, per-rule macro-F1, answer EM/F1, evidence recall/citation precision, latency, tokens, and memory size.

Required ablations: matched Cell 5 vs 6; actual Scallop vs Python fallback; remove one rule family at a time; reject-only vs replacement; self-reflection only vs rules only vs both; no provenance score; raw/flat/sparse/dense/hybrid/PPR retrieval; derived writes on/off. Use three or more paired runs, confidence intervals, and paired tests.

Reproducibility and documentation gaps

Required downloads/services are underdocumented. The project needs Qwen model weights, BGE embedding weights, datasets, Neo4j, a vLLM server, and actual Scallop for constrained Cell 6. The repository has no lockfile, Docker Compose configuration, pinned vLLM/GPU specification, or fully reproducible two-environment procedure.
  • Qwen/Qwen3-4B is downloaded by vLLM; native tool parsing uses Hermes.
  • BAAI/bge-small-en-v1.5 downloads lazily through sentence-transformers.
  • LongBench-v2, HotpotQA, and 2Wiki downloads require Hugging Face data access; datasets is used but omitted from requirements.txt.
  • matplotlib is optional for aggregation but also omitted from requirements.txt.
  • scallopy is pinned to CPython 3.10 while rlms requires Python 3.11+, requiring split environments or a validated compatibility workaround.
  • The README contains legacy macOS/Rosetta instructions alongside Linux-only package requirements and helper scripts.
