# Summer 6/20 implementation and execution contract

This document turns the AISF Plan’s Summer 6/20 recommendations into checks
that can be verified from a single experiment directory.

## Implemented architecture

- Qwen receives the question and choices before retrieval in Cells 5 and 6.
- `search_knowledge_graph` is the sparse retrieval tool; it returns structured
  facts, scores, paths, provenance, scope, and decision metadata.
- `update_working_memory` compiles selected facts into a typed artifact and
  persists its transition. Cell 5 records unconstrained transitions; Cell 6
  requires an actual `scallopy` backend and fails closed.
- Scope is typed as `example`, `session`, or `session_set`. The last mode uses
  a trusted application-owned list of source sessions; model arguments cannot
  expand it.
- Working memory includes query-aware ranking components, temporal fields,
  provenance, excluded facts, derived facts, and rule/decision versions.
- Accepted decisions, replacements, rejections, and working-memory transitions
  are retained as audit artifacts.

## Six-cell controls

| Cell | Context | Answerer | Transition constraint |
|---|---|---|---|
| 1 | Raw | Flat Qwen | n/a |
| 2 | Hybrid KG (fixed pre-retrieval) | Flat Qwen | none |
| 3 | Hybrid KG (fixed pre-retrieval) | Flat Qwen | Scallop-filtered build |
| 4 | Raw | RLM | n/a |
| 5 | Qwen-native KG tools | RLM | unconstrained update |
| 6 | Qwen-native KG tools | RLM | actual Scallop update |

The unconstrained KG is extracted and verified once. Its JSONL mirror is the
frozen candidate corpus supplied to the Scallop build, preventing a second LLM
extraction from confounding the comparison. Each run also gets unique Neo4j
session IDs, so old graph state cannot leak into a new experiment.

Hybrid is the default for all KG cells (2, 3, 5, and 6). Cells 1 and 4 remain
raw-context controls. A canonical run passes compliance only when every KG row
records the configured mode as its effective executed mode, has no retrieval
degradation, and records a dense-index identity for dense or hybrid modes.

The two raw controls expose context differently because their answerers have
different interfaces. Cell 1 is a single model call and therefore retains the
32,000-character model-window safety cap. Cell 4 defaults to the complete
document in the RLM's external REPL variable; the document is not copied into
the root model prompt. Individual recursive sub-queries are kept to 32,000
document characters and the root trajectory compacts early, so full-document
access does not imply one model call over the full document.

## Evidence generated by a run

By default, `python -m experiments.run_all` creates
`results/runs/<timestamp>_<git-sha>/` containing:

- `manifest.json` with code/data hashes, exact parameters, session IDs, tool
  and rule versions, KG artifact hashes, and per-cell status/output hashes;
- one `results.jsonl` per cell, with run/session/scope/orchestration/backend
  identity on every row;
- native tool traces for Cells 5 and 6;
- KG fact and rejection mirrors;
- `summary.csv` and the accuracy figure;
- `compliance_report.json` and `compliance_report.md`.

The compliance report fails if a requested cell is missing, has execution
errors, belongs to another run, uses a different example population, diverges
between the Cell 5/6 orchestration, or labels Cell 6 with anything other than
the actual Scallop backend.

## Execution gate

A run is evidence only when its compliance report says `PASS`. Unit tests prove
the machinery, but do not substitute for the live six-cell Qwen/Neo4j/Scallop
run. The live run must be launched on Ynez with the Hermes tool parser and the
Scallop validator endpoint available.
